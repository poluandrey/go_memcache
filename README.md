# Go memcache loader

Конкурентный загрузчик логов установленных приложений в memcached, переписанный
с Python на Go. Каждая строка входного `tsv.gz` превращается в protobuf
`UserApps`, а ключ имеет вид `<тип устройства>:<идентификатор>`.

Проект не использует сторонних Go-зависимостей: небольшой protobuf из
`appsinstalled.proto` кодируется напрямую в стандартный wire format, а запись
в memcached выполняется по его text protocol.

## Требования

- Go 1.22+
- memcached (для боевого запуска) или Docker Compose

## Сборка и тесты

```bash
go test -race ./...
go vet ./...
go build -o bin/memc-load ./cmd/memc-load
```

Тесты не требуют запущенного memcached: они проверяют разбор TSV, protobuf,
реальную конкурентность, повторы записи, порядок файлов и повреждённый gzip.

## Формат входных данных

Одна строка содержит пять полей, разделённых табуляцией:

```text
idfa\tdevice-1\t55.5\t42.0\t1,7,42
```

Поддерживаемые типы устройств: `idfa`, `gaid`, `adid`, `dvid`. Некорректные
идентификаторы приложений отбрасываются, а ошибка остальных обязательных полей
считается ошибкой строки.

## Запуск

Поднять один memcached, доступный на четырёх портах:

```bash
docker compose up -d
```

Загрузить все файлы (glob лучше заключать в кавычки, чтобы его обрабатывала
сама программа):

```bash
./bin/memc-load --pattern './data/*.tsv.gz' --workers 16 --queue-size 10000
```

Проверить данные без обращения к memcached:

```bash
go run ./cmd/memc-load --pattern './data/*.tsv.gz' --dry --verbose
```

Адреса можно переопределить флагами `--idfa`, `--gaid`, `--adid`, `--dvid`.
`--retries` задаёт число повторов после первой попытки, `--timeout` принимает
Go duration (`500ms`, `3s`), а `--max-line-bytes` ограничивает размер строки.
Полный список:

```bash
go run ./cmd/memc-load --help
```

Важно: `--dry` отключает только сетевую запись. Успешно прочитанный файл всё
равно будет помечен обработанным.

## Модель конкурентности

- Файлы сортируются по имени и обрабатываются последовательно. Для имён с
  timestamp это хронологический порядок.
- Главная goroutine читает gzip и отправляет задания в ограниченный канал.
  Заполненный канал создаёт backpressure и ограничивает расход памяти.
- Пул goroutine выполняет записи параллельно. Каждый воркер переиспользует
  отдельное TCP-соединение к каждому memcached; после ошибки соединение
  закрывается и создаётся заново перед повтором.
- `sync.WaitGroup` служит барьером между файлами. После завершения всех записей
  прочитанный файл атомарно переименовывается: `file.tsv.gz` → `.file.tsv.gz`.
  Повреждённый или недочитанный файл не переименовывается.
- Программа завершается с кодом `1`, если файл не прочитан/не переименован либо
  доля ошибок достигла 1%. В остальных случаях код возврата равен `0`.

Остановить тестовый memcached:

```bash
docker compose down
```
